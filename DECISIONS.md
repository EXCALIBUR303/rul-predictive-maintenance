## Real-model update — 2026-10-26 (supersedes the illustrative-data defaults above)

- **Source/integrity:** All twelve files now use the exact pinned PunVas mirror commit already used for FD004. HTTPS bytes match Git blob IDs from its independently fetched commit tree; SHA-256 values are frozen in `docs/data/cmapss-manifest.json`. No independent NASA signature is available. Alternative: wait for the NASA archive. Reverse: change the source only with an independently reviewed manifest; never silently update expected hashes.
- **Training budget:** All 16 checkpoints were trained from scratch on full engine-grouped 80/20 training/validation splits, seed **42**, RUL cap **125**, context **30**, MinMax preprocessing fitted on training engines only. Regimes: **1** for FD001/FD003, **6** for FD002/FD004. Existing model/trainer implementations are unchanged. Test files were used only after all training/selection runs completed. The separate `artifacts/portfolio/` and `results/portfolio/` trees preserve original published research results.
- **Exact reduced settings:** neural **3 epochs**, patience **3**, batch **256**, learning rate **0.003**, MSE loss, AdamW weight decay **0.0001**, gradient clip **1**, no data subsampling; hidden size **32**, **1** layer, dropout **0.1**, Transformer d_model **32**, **4** heads, feedforward **64**. XGBoost **120** estimators, depth **4**, learning rate **0.08**, histogram method, early stopping **15**, **2** jobs; inherited subsample/column sample **0.8**, min child weight **3**, lambda **1**. CPU torch threads **2**. Complete configurations are in `configs/portfolio/`. Alternative: original 100-epoch/three-seed research runs; reverse by training a new versioned budget and regenerating exports. Some reduced neural models perform poorly (FD001 LSTM/GRU RMSE around 40); no tuning on the test set or concealment of those results.
- **Evaluation:** UI metrics now describe these exact single-seed checkpoints on official held-out test engines, with **no variance estimate**. Published FD001/FD004 three-seed comparisons remain unchanged on disk and are no longer mixed with the new replay. Test predictions, training summaries and artifact checksums are committed. Alternative: show published scores alongside unrelated weights (rejected). Reverse: expose a distinct benchmark source selector with explicit provenance.
- **Replay:** Twelve validation engines per subset, disjoint from fitting engines, with true run-to-failure labels capped at 125. They were used for checkpoint selection, so replay residuals are validation evidence, not an unbiased final test estimate. Every cycle uses actual model predictions, including left-padded early windows. Alternative: fitted training trajectories or incomplete test trajectories; reverse by exporting a separately labeled population. API parity is verified for padded, full, final and perturbed windows for all 16 checkpoints.
- **Importance:** Replace sensor-drift bars with **permutation Δ MAE in cycles**, computed for each model over up to **512** evenly selected validation windows, one deterministic permutation (seed 42). All seven XGBoost summary features for a sensor are permuted together; neural sensor channels are permuted over windows. Negative scores and dropped sensors are retained. These are model-dependent predictive sensitivities, not SHAP values or causal effects. Alternative: SHAP/gradient attribution (more cost and differing model semantics); reverse by exporting a separately named attribution method. The bars display the six highest scores and identify their validation-window scope.
- **Static what-if:** Exact precomputed inference for **one** adjusted sensor at a time (S2/S4/S11), values **−10/−5/0/+5/+10%**, every exported cycle and all four models. Moving a slider resets the others. No additive approximation or interpolation is used. Alternative: simultaneous 21³ combinations or an illustrative surrogate (rejected). Reverse: deploy a model-aware inference service to support arbitrary combinations. Live mode still queries its configured backend model, which returns its own identity.
- **Illustrative remainder:** 30/60-cycle health policy and alert thresholds remain **illustrative** and visibly labeled; they are not calibrated maintenance limits. No confidence, causal attribution, physical digital-twin state or operational safety guarantee is invented. The decorative engine drawing is an **illustrative schematic**, explicitly labeled in the UI.
- **Persistence:** Trusted local model bundles are committed (including model/preprocessor binaries), with SHA-256 checksums. They must never be loaded from an untrusted source: joblib/torch serialization is executable. A fresh checkout can use the static UI offline or regenerate using these bundles; raw datasets are re-downloadable using the pinned manifest. No new third-party package was needed. Alternative: retain weights only in this ephemeral machine (rejected); reverse by moving verified bundles to versioned artifact storage and updating paths/hashes.

- **Progressive static delivery:** initial fleet uses a ~20 KB catalog of exact checkpoint snapshots; full per-cycle/what-if JSON loads on entering analysis views. No prediction is removed, interpolated or approximated. Alternative: load all ~5 MB initially (measured Lighthouse performance 70). Reverse: use a full-data URL override, accepting its startup cost.
